## Implementation Details

### dag.rs
- Kahn's algorithm (BFS-based topological sort)
- `DagError` enum with `CycleDetected` and `UnknownNode` variants
- Handles empty graphs, self-loops, mutual cycles, unknown node references

### scheduler.rs
- `JobScheduler` struct wiring together `WorkerPool`, `ModelRegistry`, `HardwareInfo`, `ServerConfig`
- Public API: `submit()`, `cancel()`, `get_job()`, `list_jobs()`, `subscribe_status()`, `start_dispatch_loop()`, `stop()`
- Dispatch loop: tokio-spawned task that polls queue → finds idle worker → checks VRAM → assigns job → transitions status
- Status broadcast via `broadcast::Sender<JobStatusEvent>`
- VRAM ledger initialized from hardware info with configurable budget fraction (default 90%)

## Tradeoffs
- Dispatch loop uses tokio task (not `.tick()` polling) for simpler background operation
- Scheduler tests use real `WorkerPool` + mock hardware (no Python subprocesses needed)
- Unused fields (`registry`, `config`, `tasks`) are future hooks for P1-D2+
