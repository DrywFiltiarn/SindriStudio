## Implementation Details

### managed.rs — ManagedWorker + WorkerState
- `WorkerState` enum: `Initializing`, `Idle`, `Busy { job_id }`, `Unresponsive`, `Dead`
- `ManagedWorker` struct tracks per-worker state, PID, device info, stdin handle
- Methods: `new()`, `on_ready()`, `on_event()`, `set_busy()`, `set_idle()`, `mark_dead()`, `to_worker_info()`

### pool.rs — WorkerPool
- Spawns Python worker subprocesses via `tokio::process::Command`
- Background task reads IPC frames from stdout (frame-by-frame, not read_to_end)
- Drains stderr in a separate background task to prevent pipe buffer blocking
- Broadcast channel for WorkerEvent fan-out
- APIs: `spawn_for_device()`, `spawn_initial_workers()`, `acquire_idle()`, `set_busy()`, `set_idle()`, `send_to()`, `subscribe_events()`, `status_snapshot()`, `shutdown_all()`, `worker_count()`

### Dependencies Added
- `tokio` (full features) — async process spawning and IO
- `uuid` (v4, serde) — worker ID generation
- `tracing` — logging
- `serde_json` — JSON values
- `rmp-serde` = "1" — msgpack serialization for IPC frame parsing
- `anvilml-hardware` with `mock-hardware` feature — MockHardwareDetector for tests

## Risks & Notes
- Integration tests are `#[ignore]`d because they require a live Python subprocess with the full AnvilML environment (PYTHONPATH, backend package imports). They work correctly when run manually with `--include-ignored`.
- The stdout reader uses frame-by-frame reading with 60s timeout per frame (not `read_to_end`) to handle long-lived workers that emit periodic MemoryReport events.
- stderr is drained in a background task to prevent pipe buffer blocking.
