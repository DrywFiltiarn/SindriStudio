## Plan

### Objective

Create the AnvilML backend repository structure as a Rust Cargo workspace containing 8 library crates plus a launcher binary. Each crate receives a minimal `lib.rs` or `main.rs` containing only a `//!` crate description comment and one trivial test (`assert!(true)`). ### Workspace Cargo.toml Dependencies

Following ARCHITECTURE.md, the workspace `Cargo.toml` will pin shared dependency versions:

```toml
[workspace.dependencies]
tokio       = { version = "1",   features = ["full"] }
axum        = { version = "0.7", features = ["ws", "macros"] }
serde       = { version = "1",   features = ["derive"] }
serde_json  = "1"
anyhow      = "1"
thiserror   = "1"
tracing     = "0.1"
tracing-subscriber = { version = "0.3", features = ["env-filter"] }
uuid        = { version = "1",   features = ["v4", "serde"] }
chrono      = { version = "0.4", features = ["serde"] }
sqlx        = { version = "0.8", features = ["sqlite", "runtime-tokio", "chrono", "uuid"] }
```

Each crate's `Cargo.toml` will use `{ workspace = true }` for these shared deps.

### Verification Strategy

1. **Build**: `cd backend && cargo build --workspace` must exit 0
2. **Test**: `cd backend && cargo test --workspace` must exit 0 with 9 passing tests (8 crates + launcher)
3. **Clippy**: `cd backend && cargo clippy --workspace -- -D warnings` must exit 0

All three commands must succeed before the task is considered complete.

### Decisions

1. **No external dependencies in skeleton crates**: Each `lib.rs` contains only `//!` comments and a test module. No `use` statements beyond `std` (which is implicit). This ensures `cargo clippy` has nothing to complain about.

2. **Launcher is a binary in the workspace root** (`backend/src/main.rs`), not a separate crate in `crates/`. This matches the workspace member list in ARCHITECTURE.md which has `"."` as a member alongside the `crates/*` paths.

3. **anvilml-openapi is a binary crate** (`[[bin]]` in its `Cargo.toml`), not a library crate. Its `main.rs` is the entry point. This matches the spec which says it's a "build tool, not linked at runtime."

4. **Dependency declarations in skeleton crates**: Each crate's `Cargo.toml` will declare its dependencies using `{ workspace = true }` syntax where applicable. Even though the skeleton code doesn't use these deps, declaring them is important for the workspace topology and ensures `cargo build` resolves them correctly. The crates that depend on other AnvilML crates will list them as `[dependencies]`.

5. **No `Cargo.lock` committed**: The `.gitignore` will exclude `Cargo.lock` (following Rust best practice for library workspaces — the lock file is generated locally).
