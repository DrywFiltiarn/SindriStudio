# P1-A7: anvilml-hardware — ROCm Detection (PLAN)

## Task Overview

Implement `RocmDetector` in `crates/anvilml-hardware/src/rocm.rs` that detects AMD ROCm GPUs on the system by parsing output from `rocm-smi`, `rocminfo`, and `lspci`.

**Prerequisite:** P1-A6 is COMPLETE (detector trait + CPU impl already in place).

---

## Design Decisions

### 1. Trait Alignment

The `DeviceDetector` trait (from P1-A6) defines:
```rust
async fn detect(&self) -> Result<Option<HardwareInfo>, HardwareError>;
```

The task description says "return `Ok(vec![])`" when tools are absent. This maps to returning `Ok(None)` — the trait's `Option<HardwareInfo>` return value. `detect_all_devices` already handles `Ok(None)` by skipping that detector and continuing to the next.

### 2. `RocmCapabilities` Struct

A helper struct to collect per-device capability flags, which then maps to `InferenceCaps`:
```rust
struct RocmCapabilities {
    hipblaslt: bool,
    aotriton_flash_attn: bool,
    fp8: bool,
    bf16: bool,
    rebar_enabled: bool,
}
```

This maps to `InferenceCaps` as:
- `hipblaslt` → `InferenceCaps::hipblaslt`
- `aotriton_flash_attn` → `InferenceCaps::flash_attention`
- `fp8` → `InferenceCaps::fp8`
- `bf16` → `InferenceCaps::bf16`
- `fp16` → assumed `true` for all ROCm GPUs (AMD has supported FP16 since Vega)

### 3. Version Detection

A `rocm_version_gte(major: u32, minor: u32) -> bool` helper that parses version strings like "7.0.0" or "6.3.1" and returns whether the installed ROCm version is >= the given version.

### 4. Graceful Degradation

If `rocm-smi` is not found in PATH → return `Ok(None)` with a `debug!` log. No error is returned — this allows other detectors (CPU) to fill in the host info.

## Implementation Plan

### STEP 1: Create `rocm.rs` with core structures

**File:** `crates/anvilml-hardware/src/rocm.rs`

Implement:

1. **`RocmDetector` struct** — zero-sized, implements `DeviceDetector` trait
2. **`RocmCapabilities` struct** — helper for capability detection
3. **`rocm_version_gte(major, minor) -> bool`** — version comparison helper
4. **`parse_rocm_smi_json(json: &str) -> Vec<GpuDevice>`** — parse `rocm-smi --showmeminfo vram --json` output
5. **`detect_gfx_arch(device_idx: u32) -> Option<String>`** — parse `rocminfo` output for GFX string
6. **`detect_rocm_version() -> Option<String>`** — read `/opt/rocm/.info/version` or `rocm-smi --version`
7. **`detect_rebar(device_idx: u32) -> bool`** — parse `lspci -v` for prefetchable regions > 256MB

### STEP 2: Implement `DeviceDetector` for `RocmDetector`

```rust
#[async_trait]
impl DeviceDetector for RocmDetector {
    fn device_type(&self) -> DeviceType {
        DeviceType::Rocm
    }

    async fn detect(&self) -> Result<Option<HardwareInfo>, HardwareError> {
        // 1. Check if rocm-smi exists in PATH
        // 2. If not, return Ok(None) with debug log
        // 3. Run rocm-smi --showmeminfo vram --json
        // 4. Parse JSON to get per-device VRAM info
        // 5. For each device, detect gfx_arch, version, rebar, capabilities
        // 6. Build HardwareInfo with host info (from sysinfo, like CpuDetector)
        //    and ROCm devices
        // 7. Return Ok(Some(HardwareInfo))
    }
}
```

### STEP 3: Wire into crate public API

**File:** `crates/anvilml-hardware/src/lib.rs`

Add:
```rust
pub mod rocm;
pub use rocm::RocmDetector;
```

### STEP 4: Register `RocmDetector` in `detect_all_devices`

**File:** `crates/anvilml-hardware/src/detector.rs`

Add `RocmDetector` to the default detector list in `detect_all_devices()` (or in a new `detect_all()` convenience function). The task says to "register RocmDetector" — this means `detect_all_devices` should try `RocmDetector` alongside `CpuDetector`.

### STEP 5: Write tests (fixture-based)

All tests use fixture strings — no real ROCm needed.

1. **`test_rocm_detector_missing_tool`** — `RocmDetector::detect()` returns `Ok(None)` when `rocm-smi` is not in PATH
2. **`test_parse_rocm_smi_json`** — `parse_rocm_smi_json` correctly extracts VRAM from known JSON fixture string
3. **`test_detect_gfx_arch_unavailable`** — `detect_gfx_arch` returns `None` gracefully when `rocminfo` is not in PATH
4. **`test_rocm_version_gte_true`** — `rocm_version_gte("7.0.0", 7, 0)` returns `true`
5. **`test_rocm_version_gte_false`** — `rocm_version_gte("6.3.1", 7, 0)` returns `false`

## Risk / Edge Cases

1. **`rocm-smi` JSON format may vary** — We only parse the fields we need (VRAM total/free per device). If the format changes, the parser should degrade gracefully rather than panic.

2. **`lspci` may require root** — ReBAR detection may fail on unprivileged systems. We treat this as `rebar_enabled: false` rather than an error.

3. **`rocminfo` output is unstructured text** — We use regex to extract the GFX string. If the format changes, we return `None` for `gfx_arch`.

4. **Cross-platform** — ROCm is primarily Linux, but ROCm 7.2+ ships Windows support. The `lspci` command is Linux-only; on Windows we'd need a different approach. For Phase 1, we focus on Linux.
